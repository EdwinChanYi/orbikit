# 管理后台前端交互用例

对着已登录的管理后台页面执行。不要点「构建」「部署」「回滚」去替换正在运行的容器，也不要发布一份改过的配置。

## 登录

| 编号 | 操作 | 期望 |
|---|---|---|
| UI-01 | 未登录直接打开 `/`、`/config`、`/cluster`、`/logs`、`/release` | 都回到登录页 |
| UI-02 | 空密码点登录 | 留在登录页，并提示失败 |
| UI-03 | 错误密码点登录，再按回车提交一次 | 提示「登录失败」，只发一次请求 |
| UI-04 | 正确密码登录 | 进入总览，侧栏当前项是总览，顶栏来源是 Nacos |
| UI-05 | 登录前先打开 `/config`，再登录 | 登录后回到刚才要去的配置页 |
| UI-06 | 点退出 | 回到登录页，再打开 `/` 仍要登录 |

## 导航

| 编号 | 操作 | 期望 |
|---|---|---|
| UI-07 | 依次点总览、配置、集群、日志、发布 | 地址、顶栏标题、侧栏选中项一致 |
| UI-08 | 刷新当前页，再后退、前进 | 仍保持登录，页面内容还在 |
| UI-09 | 把窗口缩到手机宽度 | 侧栏不挡住内容，主要按钮仍可点 |

## 总览

| 编号 | 操作 | 期望 |
|---|---|---|
| UI-10 | 看 etcd 和六列 | etcd 为正常；容器、gRPC、实例用中文状态，不出现原始枚举 |
| UI-11 | 看镜像和最近发布 | 长镜像可以看全；最近发布显示引用或短镜像号和时间 |
| UI-12 | 总览没有手动刷新时，等发布状态变化 | 有刷新，或明确告诉用户需要刷新 |

## 配置

| 编号 | 操作 | 期望 |
|---|---|---|
| UI-13 | 刚进配置页 | 已选中一个服务，编辑区里是它的配置，不是空白 |
| UI-14 | 切换 core、chatroom、gateway、webhook、admin、builder | 当前服务有选中态；正文、历史、灰度 IP、监听者跟着变 |
| UI-15 | 发布与当前内容相同的配置 | 有成功反馈，历史出现新记录 |
| UI-16 | 灰度 IP 填 `not-an-ip` 后点灰度 | 拒绝，并说明原因；正式配置不变 |
| UI-17 | 点停止灰度 | 有结果反馈；没有灰度时不会假装成功 |
| UI-18 | 点一条历史的回滚 | 先确认；成功后编辑区变回那一版 |
| UI-19 | 配置请求失败 | 编辑区不被清空，错误留在页面上 |

## 集群

| 编号 | 操作 | 期望 |
|---|---|---|
| UI-20 | 看状态、主节点、库大小、告警、实例表 | 状态是中文；实例包含 core、chatroom、webhook 的地址 |
| UI-21 | 状态值不在已知枚举里 | 显示原始值或「未知」，不留下空白 |

## 日志

| 编号 | 操作 | 期望 |
|---|---|---|
| UI-22 | 打开日志 | 如果还没做，空状态说明清楚，顶栏不再显示无关的「容器输出」 |

## 发布

| 编号 | 操作 | 期望 |
|---|---|---|
| UI-23 | 打开发布页 | 能看到已构建版本和远端引用；当前服务有选中态 |
| UI-24 | 切换六个服务 | 版本列表跟着变；远端引用仍在；上一个服务的错误被清掉 |
| UI-25 | 没有版本时 | 「部署」不可用，并说明没有已构建版本 |
| UI-26 | 点构建或部署 | 先确认目标服务和版本；进行中按钮禁用，状态会从排队变成结果 |
| UI-27 | 任务进行时切到另一个服务再点构建 | 被拒绝，并说明已有发布在进行 |
| UI-28 | 失败且带镜像的任务 | 能看到错误和日志；「用该镜像重建」可点 |
| UI-29 | 回滚按钮 | 只有确实有上一版时出现，点击前要确认 |
| UI-30 | 任务记录 | 能区分发布、回滚、重建；时间可读；长日志不把整页撑开 |

## 2026-11-16 实测

对着 `http://127.0.0.1:8091` 走了一遍。没有点「构建」「部署」「回滚」「用该镜像重建」，也没有发布改过的配置。builder 发过一次与当前正文相同的配置，正文没有变化，只多了一条历史。
